# Feature: visual-customization

## Objective and authorization

Implement `/gentle:customize` as a unified keyboard-accessible visual settings overlay for Gentle Shell. The user explicitly authorized implementation and clarified that “top tab” means the Gentle Shell fullscreen header, which should move below the input. Do not add adjustable width/breakpoint or accessibility controls (contrast/reduced motion). The user authorized issue, PR, and merge operations on the verified `Gentleman-Programming/gentle-shell` origin using the configured `gh` session, subject to repository policy.

## Problem and rationale

Animation and banner preferences are split across commands; themes require Pi settings or manual JSON; desktop status/header layout is fixed. A unified panel should expose the existing controls and new appearance/layout preferences without duplicating or silently overwriting their stores. A live screenshot showed the first implementation as an ugly full-screen flat 31-row list without groups or a visible preview. The user selected a compact panel with category navigation on the left and controls/modal-only preview on the right, adapting to one category per screen on narrow terminals. A second live screenshot showed the compact frameless text panel still wastes space and lacks the visual language of Commands; the user explicitly requested the same style as Commands. A third screenshot showed the theme editor still frameless and an invalid-HEX error while editing an alias-backed role. The user then requested removal of the entire custom-theme editor, including creation, editing, import and export, while keeping everything else.

## Scope and constraints

- Group existing `/gentle:animations` policies (quality/performance/potato) and banner visibility/color under the panel; preserve existing commands and persistence.
- Select installed Pi themes and preview their source palettes inside the modal without applying them; selecting an installed theme explicitly remains available. The user removed the custom-theme editor and its create/edit/import/export actions after live testing; do not expose them in the UI or leave reachable write paths.
- Configure status presentation: right, bottom, or hidden; preserve responsive default (desktop >=140 columns, narrow/regular bottom). Move the Gentle Shell fullscreen header below the input if technically supportable without breaking renderer ownership; do not move an external terminal tab.
- Configure placement of the existing top UI/header under the input, density (comfortable/compact/minimal), visibility of Changes, Agents, TODO, usage/cost and model details, reset defaults, and named visual profiles for whole-setting combinations.
- Avoid direct terminal screen/scrollback writes; use Pi-supported APIs where available and isolate any host-internal layout adaptation, testing resize, narrow mode and restoration. Confirm Pi runtime compatibility before assuming live theme APIs.
- Technical artifacts and UI copy default to English. Local implementation only. Preserve existing work and baseline compatibility.
