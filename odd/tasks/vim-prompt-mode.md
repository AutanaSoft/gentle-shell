# Vim prompt mode

## Objective
Add an opt-in `/gentle:vim` preference for Gentle Shell's prompt, following `/gentle:animations` for global persistence, status, interactive selection, and live updates. The editing semantics must match the documented Claude Code Vim editor mode, not merely a Vim-like h/j/k/l subset. Ordinary editing remains the default.

## Problem / why
Users accustomed to Vim need modal prompt navigation without replacing the existing Gentle prompt or disturbing Pi's other editor owners. Escape currently has turn-cancellation and idle-draft semantics, so mode transitions must not accidentally trigger those effects.

## Constraints and decisions
- Off by default; enabling is explicit. Follow animation policy's global persistent file and status/menu shape, including headless status fallback, invalid policy fallback, and immediate live application.
- Only the Gentle-owned prompt uses modal editing. User explicitly authorized a larger owned input-editor redesign after the Pi 0.85.1 visual-selection proof failed. Preserve the existing Gentle frame, avoid replacing a foreign editor, and do not modify Pi core.
- Source of truth: https://code.claude.com/docs/en/interactive-mode#vim-editor-mode (public docs fetched directly). Match its documented prompt command families: INSERT/NORMAL/VISUAL character/line modes; `i/I/a/A/o/O`, `h/j/k/l`, Space, `w/e/b`, `0/^/$`, `gg/G`, `f/F/t/T` and `;/,`; keep `/` for Pi commands and skills even in NORMAL; reverse prompt-history search is excluded by explicit user choice; edit `x`, `d/c/y` line/word/find motions, `s/S`, `p/P`, indent/dedent, `J`, `u`, `.`, text objects (word/WORD/quotes/brackets), visual operators, and `Ctrl+[` where Pi receives it. Block-wise visual is explicitly not supported by Claude Code. Do not advertise features not actually implemented.
- Explicit user choice: in INSERT, Escape only enters NORMAL, never cancels a running turn or clears a draft; subsequent Escape in NORMAL follows existing Gentle Escape semantics. This is a Gentle override of Claude Code's otherwise modal Escape, and must be visible in docs. Preserve autocomplete, queue/abort, bash-mode, empty-draft and double-Esc behavior with tests.
- Use Pi's existing editor owner/shortcut/autocomplete contracts. No silent NORMAL writes from encoded keys, paste, autocomplete or shell-mode. Preserve cursor, undo and any paste markers. Pi 0.85.1 public editor API cannot set cursor, edit a range atomically or render visual selection. Before expanding commands, prove a narrow version-gated private adapter in isolation with tests; fail closed on unknown layout. Do not mutate private state without that proof.
- Existing MIT pi-vim reference (https://github.com/burneikis/pi-vim) implements many families but targets `@mariozechner/pi-*`, replaces the editor factory, and accesses private state. The MIT `@0xkahi/pi-vim-keys` 1.1.2 reference (https://github.com/0xKahi/pi-vim-keys) highlights visual selections by overlaying visible wrapped rows after `super.render`, capturing the scroll offset from `renderTopBorder`; its private-state/word-wrap dependencies have drift tests. Its dev dependencies target Pi 0.87, so behavior against our installed Pi 0.85.1 is unproven. Study its design/tests, but preserve the Gentle editor factory, live toggle, frame, and Esc semantics; do not install either package as another editor owner or copy code without MIT attribution.

- Advisory task sizing: ~400 authored changed lines per work unit is a heuristic, not a hard acceptance limit. Do not omit tests or compress code to fit it.

## Acceptance criteria
- `/gentle:vim` offers a selector in interactive mode and status headlessly; `enable`, `disable`, and `status` report effective mode and persist as animation policy does.
- Existing prompt instances switch immediately; new sessions load the persisted choice. Disabled mode preserves all pre-existing editing behavior.
- Documented Claude Code Vim command families above work on Unicode/multiline prompts, including visual selection/operators. `/` continues to open Pi commands and skills, including from NORMAL, by explicit user choice; reverse prompt-history search is omitted and documented as a deliberate divergence. Other unsupported commands are reported honestly. Escape follows the user's explicit two-stage Gentle decision without discarding queued text.
- No text-producing NORMAL-mode path, app shortcut, autocomplete or shell-mode silently changes the draft. Owned-editor guard, tests and typecheck remain intact.
