# Fullscreen Scroll Cache

## Objective and problem
Make scrolling a long Pi conversation responsive in Gentle Shell fullscreen with the desktop sidebar, without changing visible output or disabling the sidebar. Fullscreen at narrow/mobile widths without the sidebar is the comparison case. Inspired by pi-render-cache's bounded, independently validated caching and fail-closed approach, but targeting the observed scroll path rather than assuming streaming Markdown is the bottleneck.

## Evidence and next step
Upstream pi-render-cache reports streaming and Unicode-width replay on Pi 0.84.1, not long-history scroll with sidebar. Installed package pins pi-tui 0.85.1. Pi's layout render cache is frame-local; settled Markdown components cache lines by text and width; sidebar's section memo does not cache the transcript. T1 baseline (native Pi 0.85.1 TuiAltScreen/createChatViewport, 24 rows, 15 scroll frames/configuration; synthetic settled 120/1200-row ASCII, styled ANSI and real Markdown fixtures): tests passed 2/2, existing fullscreen tests passed 2/2; `git diff --check` and explicit untracked-file whitespace check passed. At 140 columns with sidebar the transcript is 87 columns. In a representative rerun, 1200-row Markdown cache-hit scroll median was 0.34 ms with sidebar vs 0.024 ms in an 87-column no-sidebar control, with 0 Markdown misses; 120-row was 0.377 vs 0.032 ms. Forced invalidation of the Markdown instance gave 1200-row 73.363 vs 72.431 ms and 15 misses, so the history-dependent cold work occurs in both layouts, not uniquely in the sidebar. Styled ANSI showed the same pattern: settled 1200-row 0.287 vs 0.027 ms, invalidated 64.209 vs 63.394 ms. Narrow 100-column sidebar-installed layout matched native control bytes. Desktop controls compared matching transcript pixels and width; screen geometry differs intentionally. These synthetic short-run medians are diagnostic, not live latency, and do not reproduce a multi-second freeze. T1's measured excess points to viewport side-by-side composition on cache hits; streaming-oriented Markdown caching is not the first fix. Next: T2 find a safe local way to reuse unchanged composition or stop at Pi-internal boundary.
