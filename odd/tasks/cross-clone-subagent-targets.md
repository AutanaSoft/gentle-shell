# Authorized cross-clone subagent targets

## Objective and problem
Let a Pi session rooted in Gentle AI explicitly launch a bounded subagent in a separate Gentle Pi Git clone without changing the parent's cwd or treating that clone as one of its linked worktrees. Today `subagent_run.workspace_root` calls the same-clone `SessionWorktreeRegistry.validate()` and rejects a different Git common directory before queueing.

## Scope and constraints
- Work only in the isolated `feat/cross-clone-subagent-targets` worktree; preserve both repositories' existing worktrees and unrelated changes.
- Keep `SessionWorktreeRegistry.validate/register` same-clone-only for Changes, footer/widget counts, and durable worktree entries. A foreign child must not register its root in the parent's Changes scope.
- A foreign destination must be an explicit existing canonical Git worktree. Resolve the canonical root and Git common directory from Git, not from model prose, a path alias, or inherited `GIT_*` routing.
- Obtain an interactive human grant before any queue or child session-directory write. Bind the grant to the live session identity and the destination's canonical Git common directory. The user chose one grant per foreign clone for the current session; later launches in that same live session may reuse it. No UI, cancelled/declined consent, missing/changed identity, or a new session fails closed. A reload that loses the live grant must fail closed rather than silently recreate it.
- Do not allow task text or tool arguments to mint a grant. Same-clone child behavior and existing SDD/remediation/review guards stay intact. Keep child cwd and model-profile selection bound to the validated destination.
- No push, PR, merge, or release is authorized for this feature by the present request.
